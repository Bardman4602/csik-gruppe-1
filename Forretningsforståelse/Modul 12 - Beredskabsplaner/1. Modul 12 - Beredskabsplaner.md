## Noter (AI)

**Continuity Management & Cybersikkerhed**

> En god beredskabsplan kan være forskellen på virksomhedens overlevelse og lukning.

---

### Hvorfor er beredskabsplaner vigtige?
- **Opretholder drift under angreb** → fokus på kritiske funktioner.
- **Reducerer nedetid og økonomisk tab**.
- **Lovkrav** i bl.a. **NIS2 og GDPR**.
- Øger **cyberresiliens** (evnen til at modstå, håndtere og genoprette).

---

### Fire centrale plan-typer

| Plan                               | Fokus                                    | Formål                         |
| ---------------------------------- | ---------------------------------------- | ------------------------------ |
| **IRP – Incident Response Plan**   | Håndtering af angreb                     | Playbooks & hændelsesstyring   |
| **DRP – Disaster Recovery Plan**   | Teknisk gendannelse                      | Genskabe data & systemer       |
| **BCP – Business Continuity Plan** | Sørger for at virksomheden kan fortsætte | Holde drift kørende uden IT    |
| **CMP – Crisis Management Plan**   | Ledelse & kommunikation                  | Koordinering, beslutninger, PR |

> *Underleverandører skal også kunne dokumentere planer.*

---

### Fundament for beredskabsplaner

| Element                   | Betydning                                            |
| ------------------------- | ---------------------------------------------------- |
| **Forretningsforståelse** | Kendskab til mål, processer og værdikæde             |
| **Roller og ansvar**      | Ejerskab, beslutningskraft og kompetencer            |
| **Kritiske processer**    | De aktiviteter, der holder virksomheden i live       |
| **Risikostyring**         | Identifikation af trusler, sårbarheder og konsekvens |
| **Afhængigheder**         | Leverandører, netværk, applikationer, data m.m.      |

---

### BIA – Business Impact Analysis

> BIA er fundamentet for alle beredskabsplaner.  
> Den definerer *hvad der er kritisk, hvor hurtigt det skal genoprettes og hvor meget data der må tabes.*

#### Centrale elementer i BIA

| Element                            | Forklaring                                      |
| ---------------------------------- | ----------------------------------------------- |
| **Identifikation af processer**    | Kortlægning af virksomhedens drift              |
| **Kritikalitet**                   | Hvad er vigtigst for virksomhedens overlevelse? |
| **Konsekvensanalyse**              | Økonomi, lovkrav, omdømme, sikkerhed, drift     |
| **RTO (Recovery Time Objective)**  | Maksimal nedetid                                |
| **RPO (Recovery Point Objective)** | Maksimalt datatab (målt i tid)                  |
| **Afhængigheder**                  | Leverandører, systemer, data, netværk           |
| **Prioritering**                   | Hvad gendannes først — og hvorfor?              |

---

#### BIA – mål
- Understøtte udvikling af **BCP, DRP og IRP**.
- Dokumentere evnen til at **nå RTO og RPO**.
- Forstå og beskytte kritiske aktiver.
- Prioritere ressourcer på baggrund af forretningen.

---

## Nøglebegreber (hurtig reference)

| Begreb  | Definition                                |
| ------- | ----------------------------------------- |
| **RTO** | Hvor længe noget må være nede             |
| **RPO** | Hvor meget data (tid) må mistes           |
| **BCP** | Plan der holder forretningen i gang       |
| **DRP** | Teknisk gendannelsesplan                  |
| **IRP** | Plan for håndtering af angreb             |
| **CMP** | Ledelses- og kommunikationsplan           |
| **BIA** | Analyse af hvad der er kritisk og hvorfor |

---

## Relation mellem risiko, BIA og beredskab

### Risikostyring → BIA → Beredskabsplaner → Test & Øvelser


- Risiko viser **hvor problemerne kan opstå**
- BIA viser **hvad vi ikke kan undvære**
- Planer viser **hvordan vi reagerer**
- Test viser **om vi faktisk kan udføre planen**
